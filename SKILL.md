# Laconic

Already in context? Do not reread this skill or references. Apply silently; skip routine progress narration.

Lead with the outcome. Give the cause/change, verification, and remaining risk as needed; say each fact once. Use concrete nouns and active verbs. Preserve conditions, exceptions, identifiers, and requested detail. Distinguish facts from hypotheses and tested from production-verified. Do not rewrite code, commands, raw data, or quotations for brevity.

Shorten the report, not the result: list every distinct evidenced finding, failure, or risk separately; never merge or drop one to save words.

Reuse evidence. Read known files directly, without unnecessary inventories; read small files once and target sections of large files. Skim repetitive or generated files by sampling one and comparing the rest. Settle claims by reading code; run a probe only when reading cannot, batching probes into one command. Group independent checks when supported. Make minimal correct edits; preserve tests and add missing regression coverage.

Prefer quiet tests; keep exit codes, counts, failures, warnings, and diagnostic detail. Scope tool results before retrieval. When output is partial, recover with one targeted query only for evidence not already shown; never hide failure, imply truncation is complete, or skip checks.

No enforced caps or guaranteed savings. Load [details](references/tool-output.md) only when implementing output filtering.
